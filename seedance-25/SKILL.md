# Seedance 2.5 프롬프트 생성기

Seedance 2.5는 2.0과 **프롬프트 문법이 다르다.** 2.0용 프롬프트를 그대로 넣으면 2.5의 핵심(타임스탬프 초 단위 통제, @소재 지시, 30초 단발, 네거티브 준수)을 하나도 못 쓴다.
이 스킬은 ByteDance 공식 가이드의 공식을 그대로 구현한 것 — 감으로 쓰지 말고 공식대로 조립해라.

**출처:** ByteDance 공식 【Dreamina】Seedance 2.5 User Guide (2026-08-04 수정본) 기준.

---

## 0. 먼저 모드부터 판정한다

프롬프트 문법이 모드마다 완전히 다르다. 사용자 요청을 읽고 아래에서 **하나**를 고른다. 애매하면 그때만 물어본다.

| 사용자가 원하는 것 | 모드 | 쓸 공식 |
|---|---|---|
| 새 영상 4~30초, 레퍼런스 있어도 되고 없어도 됨 | **Omni Reference** (기본) | `references/formulas.md` § A 기본공식 / § C 30초공식 |
| 30~180초를 한 방에 | **Long Video** | § D 초장편공식 |
| 이미 만든 영상 뒤에 이어붙이기 | **Extend Video** | § E 연장공식 (+ `transitions.md`) |
| 만든 영상의 일부만 고치기 (물건 교체·제거·색 변경) | **Smart Edit / Edit with marks** | § F 편집공식 |
| Maya/Blender 화이트모델 → 렌더 | **Clay Renderer** | § G 화이트모델공식 |

> 20초를 넘기면 무조건 § C(타임스탬프 모듈 구조)로 간다. § A 기본공식은 15초 이하 단발용이다.

## 1. 인터뷰 — 빈칸만 묻는다

이미 대화에 나온 건 **다시 묻지 마라.** 아래 중 비어 있고, 없으면 결과가 달라지는 것만 최대 3개까지 묻는다.

필수로 알아야 하는 것:
1. **길이 + 비율** (예: 15초 / 9:16). 없으면 9:16 · 15초로 잡고 그렇게 썼다고 밝힌다.
2. **업로드할 소재**가 있나 — 이미지 / 영상 / 오디오 각각 몇 개, 각각 뭘 위한 건지(인물 얼굴 / 음색 / 동작 / 장면 / 화이트모델).
3. **컷이 나뉘나, 원테이크인가.** 나뉘면 트랜지션 종류를 `transitions.md`에서 추천한다.

물어보지 말고 알아서 채우는 것: 조명, 렌즈, 질감 어휘, 네거티브 문구, 카메라 무빙 → `references/lexicon.md`에서 뽑아 쓴다.

## 2. 조립 — 4블록 골격

모든 모드가 이 골격을 공유한다. 모드별 변형은 `formulas.md`.

```
[① 소재 설명]  업로드 순서대로 번호 + 용도
[② 한 줄 요약]  주체 + 장소 + 사건 + 스타일 + 특수 카메라무빙
[③ 플롯 본문]  타임라인 슬라이스마다  ➕할 것 / ➖하지 말 것
[④ 전역 보충]  끝에서 다시 한 번: 카메라 포지션 + 환경 + 사운드/분위기 + 조명 + 전역 금지
```

**④는 빼먹지 마라.** 2.5가 프롬프트 끝에서 전역 제약을 다시 읽는 구조라 여기 안 쓴 건 중간에 무너진다.

### 반드시 지키는 5가지 규칙

1. **소재는 @로 부른다.** `@image1`, `@video2`, `@audio1`. 본문 안에서 **여러 번 반복해서** @해라 — 공식 가이드가 "여러 번 @할수록 정확해진다"고 명시한다. 번호는 **업로드 순서**다.
2. **타임스탬프는 초 단위로 명시한다.** `0s-3s:` `3s-8s:` 형식. 2.5는 순서가 아니라 진짜 초를 지킨다. 슬라이스 하나에 [구간] + [코어 단계] + [물리적 동작 지시] + [감정/카메라 스케줄링] 4개를 다 쓴다.
3. **네거티브를 본문 안에 쓴다.** 별도 필드가 없다. 슬라이스마다 ➖ 한 줄 + ④에서 전역 반복. 기본 세트: `no subtitles, no on-screen text, no background music, no watermark`.
4. **언어 — 묘사는 영어, 대사는 원어.**
   - 통제·묘사문: **영어**(중국어도 동급). 공식 문서상 최적화 1순위 언어군이다.
   - 캐릭터 대사: **말하게 할 언어 그대로** 쓴다. 한국어 대사면 한국어로 그냥 쓴다 — 2.5는 한국어 발음·립싱크를 그 언어로 뽑는다. 영어로 번역해서 넣으면 영어로 말한다.
   - 사용자가 "전부 한국어로 써줘" 하면 전부 한국어로 쓰되, 최적화 1순위 언어가 아니라는 점만 한 줄로 알린다.
5. **인물이 나오면 8차원 인물 공식을 쓴다.** "예쁜 여자"로 쓰면 즉몽 얼굴(AI티)이 나온다. `formulas.md` § B 8차원을 채워라. 최소 [나이/인종] [피부톤+질감] [이목구비 3~4개] [눈빛] [헤어] [의상+소재] [체형/기질]. `retaining the true micro pores and skin texture` 같은 리얼리즘 강제 접미사를 꼭 붙인다.

## 3. 출력 형식

항상 이 4개를 순서대로 낸다. 설명 문단으로 감싸지 말고 바로 준다.

**① 설정 한 줄**
`모드: Omni Reference / 비율: 9:16 / 해상도: 720p / 길이: 15s`

**② 업로드 소재 순서표** (소재가 있을 때만)

| 순서 | 종류 | 파일 | 프롬프트에서 부르는 이름 | 용도 |
|---|---|---|---|---|
| 1 | 이미지 | model_front.png | @image1 | 주인공 얼굴 락 |

**③ 프롬프트** — 코드펜스 안에 통으로. 주석·꺾쇠 플레이스홀더 남기지 마라. 바로 붙여넣어 돌아가는 완성문이어야 한다.

**④ 자가검증 체크** — 아래 통과했는지 한 줄씩. 실패한 게 있으면 고쳐서 다시 낸다.
- [ ] 소재를 본문에서 2회 이상 @했나
- [ ] 초 구간이 요청 길이와 정확히 맞아떨어지나 (합계 = 총 길이)
- [ ] 슬라이스마다 카메라 지시가 있나
- [ ] 네거티브가 슬라이스 + 전역 양쪽에 있나
- [ ] 인물이 있으면 8차원이 채워졌나
- [ ] 컷이 있으면 트랜지션 타입을 명시했나 (하드컷 금지 문구 포함)
- [ ] 파라미터가 스펙 한계 안인가 (`specs.md`)

## 4. 흔한 실패와 처방

| 증상 | 원인 | 처방 |
|---|---|---|
| 얼굴이 AI티 남 / 즉몽 얼굴 | 인물 묘사가 추상적 | 8차원 공식 + 모공·피부결 강제 접미사 |
| 여러 명이 쌍둥이처럼 나옴 | 인물별 소재 바인딩 없음 | 인물마다 별도 이미지 업로드 + `@image1 is A, @image2 is B` 명시, 각자 의상까지 분리 서술 |
| 자막·BGM이 멋대로 붙음 | 네거티브가 전역에만 있음 | 슬라이스마다 ➖ 반복 + ④에 다시 |
| 컷이 딱딱하게 끊김 | 트랜지션 미지정 | `transitions.md`에서 타입 골라 3줄 공식으로 |
| 후반부가 무너짐 | 전역 보충 누락 / 20초 넘는데 기본공식 씀 | ④ 추가 + § C 모듈 구조로 재작성 |
| 원하는 초에 동작이 안 일어남 | 타임스탬프가 순서만 표현 | `0s-3s:` 형식으로 구간 명시 |
| 소재 많이 넣었더니 불안정 | 주체 과다 | 주체 1~5개로 줄이기 (6~10은 뽑기 운) |
